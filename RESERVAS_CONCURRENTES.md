# Reservas concurrentes
Migración aditiva 15ª tabla retenciones_plaza. npx prisma migrate deploy; npx prisma generate; npm run build; npm test. Retención global de 30 s por plaza, token privado, no se renueva automáticamente. La PK de plaza y SELECT FOR UPDATE serializan la selección. Confirmación bloquea vehículo y plaza, revalida estado físico y plazo, rechaza solapamiento por plaza o vehículo, crea reserva y consume retención en una transacción ReadCommitted. Cancelación del dueño libera su horario. Limpieza periódica elimina retenciones vencidas y marca reservas no usadas vencidas. No mueve barreras ni cobra. Vehículos verificados (seed de feria). La disponibilidad pública solo contiene código de plaza, horarios y vencimientos; no JWT, identidad ni matrícula. WebSocket reservas.actualizadas es una señal de invalidación emitida tras commit; REST obtiene datos vigentes.
Para pruebas sin PCB, enviar POST /sensores/lecturas {"sensorCodigo":"IR02","ocupado":false} desde Insomnia y repetir si pasan 90 s. Alternativa exclusiva de feria local: RESERVAS_PERMITIR_LECTURA_ANTIGUA=1 en .env (no producción); solo admite estado LIBRE con lectura previa. No representa confirmación física actual.
GET /reservas/disponibilidad público; POST /reservas/retenciones {"plaza":"P2"} con JWT; POST /reservas {"token":"...","vehiculoId":1,"fechaInicio":"2026-11-25T09:00:00-04:00","fechaFin":"2026-11-25T11:00:00-04:00"} JWT; DELETE /reservas/retenciones/:token; GET /reservas y DELETE /reservas/:codigo solo propietario. Usar fechas futuras y vehículo propio. Probar dos cuentas: una retención 201 y otra 409, vencimiento y recuperación, misma franja 409, cancelación y nueva reserva. Probar simultaneidad real, no solo secuencial; aún pendiente ejecutar localmente. No publicar endpoints de sensores simulados en Internet.
